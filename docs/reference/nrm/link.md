A connection between two ports: RFC 8345's link, carrying Redfish Cable's physical attributes.

Two things here are load-bearing.

First, `key` is content-addressable -- derived from the two endpoints rather than minted -- following UFM's convention. An expected link read from a cabling file and an observed link discovered on the fabric compute the SAME key, so the diff between plan and reality is a set operation instead of a matching heuristic. That diff is the validation product.

Second, `supporting_link_id` layers a link over the one carrying it, again from RFC 8345. An NVLink between two GPUs is supported by a physical cable cartridge; they are different links with different endpoints, and collapsing them loses the ability to say 'these six NVLink failures are one bad cartridge'. Diagnosing that distinction by hand is the kind of afternoon this field exists to prevent.
